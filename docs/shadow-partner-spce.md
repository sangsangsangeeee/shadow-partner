# 쉐도우 코치 — 기획 및 정책 v2.0

킥복싱 쉐도우 트레이닝용 개인 도구. 체육관에서 배운 콤보를 **내 목소리로 녹음**해 두고, 라운드 중에 **그 녹음이 리듬 그대로** 나온다.

**v1에서 바뀐 것** — 코치가 TTS로 동작 이름을 읽어 주던 것을 버렸다. TTS는 말 하나를 읽는 시간보다 짧은 간격을 못 내서
콤보의 리듬을 못 담는다(11장). 이제 콤보는 동작의 나열이 아니라 **녹음 하나**다. 동작·호출어·파서·리듬 모델이 같이 나갔다.

---

## 1. 제품 정의

**해결하는 문제**
체육관에서 배운 콤보를 집에 오면 까먹는다. 기존 앱들은 *앱이 생성한 콤보*를 불러주는 생성기 중심이라, *내가 배운 콤보*를 드릴하는 용도로는 어긋난다.
배운 건 동작의 나열이 아니라 **어디서 몰아치고 어디서 쉬는지**까지다. 그건 글로 못 적고 말로는 담긴다.

**사용자**
본인. 배포·수익화 계획 없음. **iOS.** 안드로이드는 마이크가 되는지 확인 못 했다(9장).

**범위 밖**
계정, 동기화, 통계 누적, 소셜, 튜토리얼 영상, 자세 인식, 음성 인식(녹음을 글로 옮기는 것).

## 2. 설계 원칙

원칙은 취향이 아니라 이 앱의 사용 맥락에서 나온다. 충돌하면 위쪽이 이긴다.

| #   | 원칙                                       | 근거                                                                                                                  |
| --- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| 1   | **화면을 안 봐도 훈련이 된다**             | 쉐도우복싱은 거울이나 허공을 봐야 한다. 화면은 보조이지 주인공이 아니다.                                              |
| 2   | **죽은 버튼을 두지 않는다**                | 비활성 버튼은 클릭 이벤트조차 발생하지 않아 "고장"으로 읽힌다. 실제로 이 앱에서 시작 버튼이 이 문제로 두 차례 막혔다. |
| 3   | **적는 마찰이 없다**                       | 이 앱의 유일한 차별점. 말하면 끝이다. 형식을 강제하는 순간 존재 이유가 사라진다.                                       |
| 4   | **되돌릴 수 있으면 확인하지 않는다**       | 확인 단계와 되돌리기를 둘 다 두면 마찰만 늘고 안전은 그대로다.                                                        |
| 5   | **떠 있는 것은 최소한으로**                | 하단 플로팅 요소가 겹치면 콘텐츠가 밀린다. 층마다 존재 이유가 있어야 한다.                                            |
| 6   | **부가 기능 실패가 본 기능을 막지 않는다** | 오디오·저장소가 없는 환경에서도 타이머는 돌아야 한다. **마이크는 예외다** — 아래.                                     |

**마이크는 부가가 아니라 본 기능이다.** 콤보를 만드는 유일한 길이라, 없으면 이 앱은 타이머일 뿐이다.
그래서 앱을 열 때 마이크를 못 쓰면 작은 알림을 띄운다(4.4). 타이머는 그래도 돈다 — 원칙 6은 거기까지다.

### 색상

블랙, 화이트, `#006064` 세 가지. 상수 `ACCENT` 하나로 관리한다.
회색 계열은 블랙-화이트 사이 톤이므로 팔레트 위반이 아니다.
`#006064`는 검정 위에서 어두워 **본문 텍스트에는 쓰지 않는다.** 배경·테두리·강조 링에만 쓴다.

## 3. 정보 구조

```
쉐도우 코치
├─ 훈련 (탭)
│   ├─ 훈련 설정 ......... 바텀시트
│   └─ 훈련 완료 ......... 전체 화면
└─ 콤보 (탭) ............. 녹음 무대 + 이름 + 목록
```

탭 2개는 하단 플로팅 바. 아이콘 위, 한글 아래.

**갔다가 돌아오는 화면은 전부 바텀시트다.** 전체 화면은 훈련 완료 하나만 남는다 —
나가는 길을 우리가 정하는 화면이라 뒤로가기가 있으면 안 된다.

이 결론은 두 번 뒤집혔다. 원래 전부 겹침(RN `Modal`)이었는데, 겹침은 별도 네이티브 층이라
**토스 상태바까지 덮어버리고** 토스는 그 헤더를 숨기는 길을 주지 않는다. 그래서 라우트로 내보냈다.
라우트는 그 문제를 풀었지만 값을 물었다 — 돌아올 때 결과를 못 들고 오고,
화면이 갈라져 자료를 트리 밖으로 빼야 했고, 전환 중 흰 번쩍임·키보드·자동 포커스를 각각 손봐야 했다.

TDS 바텀시트는 `Modal`이 아니라 **앱 트리 안의 `position:absolute` 뷰**다
(`BottomSheetRoot`). 그래서 토스 헤더를 덮지 않으면서도 라우트가 물던 값을 전부 안 문다.
문제는 "겹침"이 아니라 "네이티브 층"이었다. 시트는 아래에서 올라온다(TDS `spring.quick` 고정).

지금 시트는 설정 하나뿐이다. 동작 고르기·동작 추가 시트는 v1과 함께 나갔다.

## 4. 화면 명세

### 4.1 훈련

**목적** 라운드를 돌리고 콤보를 듣는다. 앱의 기본 화면.

**구성**

| 요소          | 설명                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------- |
| 원형 스톱워치 | 320px. 남은 시간이 링으로 줄어든다. 중앙에 시간, 그 위에 상태(`라운드 2 / 3`, `휴식`, `준비`) |
| 지금 콤보     | 나오고 있는 콤보의 **이름 하나**, 그 아래 녹음 길이만큼 차는 **막대 하나**                    |
| 유지 구간     | 콤보 사이 빈 시간. 점선 칩에 안내(`스텝`, `가드 올리고` 등), 회색 게이지로 다음 콤보까지 표시 |
| 컨트롤        | 대기 시 `시작` / 진행 중 `일시정지`·`건너뛰기`·`정지`                                         |
| 요약 알약     | `랜덤 · 3라운드 · 3:00 / 1:00`. 현재 설정 표시 겸 설정 시트 입구                              |

**정책**

- 상태 표시는 절대 배치라 비어 있어도 시간의 중앙 정렬에 영향을 주지 않는다.
- 콤보가 나올 때 보이는 건 이름과 막대뿐이다. 동작별 칩은 없다 — 동작이라는 것이 없다. 원칙 1에 오히려 가깝다.
- 유지 구간 안내는 **소리를 내지 않는다.** 3분에 30회 가까이 되어 시끄럽고, 진짜 호출과 헷갈린다.
- 진행 중 스킵은 `없음` 모드에서 숨긴다. 부를 콤보가 없다.
- 일시정지 후 재개하면 콤보를 **처음부터** 다시 튼다. 중간 복구는 복잡도 대비 실익이 없다.
- **앱을 나가면 일시정지한다.** 돌아와도 저절로 안 이어진다 — 8장 "앱을 나갔을 때".
- `횟수` 모드에서 일시정지 후 재개하면 남은 횟수를 남은 시간에 재배분한다. 총 횟수가 보장된다.

**흐름**

```
대기 ──시작──▶ 준비(5초, 비프)
                  │ 벨 3회
                  ▼
              라운드 ◀──────┐
                  │          │ 벨 3회
     10초 전 클래퍼          │
                  │ 벨 1회   │
                  ▼          │
          마지막 라운드? ─N─▶ 휴식
                  │Y
                  ▼
              훈련 완료
```

**실패 처리**
`시작`은 상태 전환을 먼저 수행하고 소리·화면잠금은 그 뒤에 시도한다.
부가 기능이 실패해도 타이머는 반드시 돈다. (원칙 6)

### 4.2 훈련 설정 — 바텀시트

**목적** 훈련 관련 설정 전부. 입구는 요약 알약과 톱니 두 곳이지만 **화면은 하나다.**

> 모드 버튼을 눌러 시트를 여는 안은 폐기했다. 선택과 열기를 한 버튼이 겸하면 예측이 안 되고, `없음` 모드는 설정할 것이 없어 예외가 생기며, 설정 입구가 둘로 갈린다.

**구성** 모드 → 라운드 → 라운드당 호출 → 라운드 시간 → 휴식 / 템포 → 콤보 간격 → 간격 불규칙 / 벨 테스트

**정책**

- 훈련 중에는 **모드·라운드·시간·휴식이 잠긴다**(투명도 40%). 진행 중인 타이머와 스케줄을 깨뜨린다.
- 반대로 **템포·간격은 살아 있다.** 라운드 중에 "너무 빠르다" 싶으면 즉시 늦출 수 있다.
- **템포는 녹음의 재생 속도다.** 0.8~1.3. 음정이 같이 변한다 — 목소리가 올라가거나 내려간다. 그게 싫으면 1.0.
  v1의 0.5~2.0은 동작 길이를 나누는 배율이라 그만큼 넓었다. 재생 속도는 그 폭에서 목소리가 망가진다.
- 잠긴 이유를 시트 상단에 한 줄로 알린다.
- 시간 설정은 스테퍼(`3:00` 표기). 숫자 입력창은 키보드를 부르고 초 단위 환산을 요구한다.
- `벨 테스트`는 라운드 벨을 한 번 친다. 소리가 나는지 훈련 전에 안다.

### 4.3 훈련 완료 — 전체 화면

**목적** 마친 직후는 앱을 다시 열게 만드는 유일한 순간. 여기서 뭘 했는지 보여준다.

**구성** `STAGE CLEAR` → `수고했어` → 통계 → `TO BE CONTINUED...` → `한 번 더` / `그만하기`

**정책**

- 절제된 다른 화면과 달리 **여기에만 성격을 몰아준다.** 숫자 카운트업(900ms, 감속), 모노스페이스 자간, `step-end` 깜빡임.
- `TO BE CONTINUED...`는 흰색. 액센트는 검정 위에서 어둡고, 오락실 화면도 흰색·노란색이 깜빡인다.
- 통계는 라운드 수·시간·**콤보 수**. 동작 수는 없다 — 동작이 없다.
- 통계는 세션 시작 시 초기화되고 콤보가 호출될 때마다 누적된다. **저장하지 않는다** — 기록 누적은 범위 밖.
- 탭바까지 덮는다. 나가는 길은 두 버튼뿐.

### 4.4 콤보

**목적** 콤보를 **말해서** 담고, 이름을 붙이고, 훈련에 넣을 것을 고른다.

**구성** 무대 → 이름 입력 → 콤보 카드 목록 / 하단 저장 버튼

**흐름**

```
쉬는 무대 ──누름──▶ 녹음 중 ──완료──▶ 이름 붙이기 ──저장──▶ 목록 맨 위
                       │ 취소              │ 다시 녹음
                       ▼                   ▼
                     쉬는 무대           녹음 중
```

**무대의 상태**

| 상태     | 무대에 보이는 것                                   | 아래                                  |
| -------- | -------------------------------------------------- | ------------------------------------- |
| 쉼       | `눌러서 녹음`                                       | 카드 목록                             |
| 녹음 중  | 경과 초(`3.2`) · `● 말해` · `취소` `완료`           | 목록은 흐리고 안 눌린다               |
| 이름     | `녹음 2.3초` · `듣기` `다시 녹음` `취소` · 이름 입력 | 카드 목록. 저장 버튼이 키보드 위에    |
| 마이크 X | `마이크를 못 써 — 콤보를 만들 수 없어`             | 카드 목록                             |

**무대**

- 콤보 탭 **상단, 고정 높이.** 시트가 아니다 — 시트의 끌어서 닫기가 누르는 손과 싸운다. 전체 화면도 아니다(3장).
- **누르면 녹음이 시작된다.** 시작 버튼을 따로 두지 않는다. 쉬는 무대에는 `눌러서 녹음` 한 줄만.
- 녹음 중에는 **경과 초**가 보인다. `● 말해` 한 줄. 아래에 `취소` `완료`.
- 끝은 **명시적 완료 버튼.** 마지막 마디 뒤의 쉼을 자동으로 끝으로 치면 콤보가 잘린다. **8초에 닿으면 저절로 완료된다** —
  콤보 하나는 그 안에 끝나고, 녹음은 초당 25KB라 길이를 열어 두면 저장소가 무너진다(5장).
- 취소는 언제든. 녹음을 버리고 쉬는 무대로.
- 녹음 중에는 **목록을 죽인다**(흐리게, 터치·스크롤 없음). 무대 밖으로 흐른 손이 카드를 누르면 안 된다.
- 마이크를 못 쓰면 무대가 한 줄로 이유를 말한다. 그 이상은 할 수 있는 게 없다 — 콤보를 만드는 다른 길은 없다.

**마이크 알림**
앱을 열 때 엔진이 마이크 API가 없는 환경이면 작은 알림을 한 번 띄운다 — `이 기기에서는 마이크를 못 써서 콤보를 만들 수 없어. 훈련 타이머는 돼.`
권한 거부는 첫 녹음 때 드러나므로 그때 무대가 말한다. 알림은 세션마다 한 번, 닫으면 끝.

**앞뒤 침묵**
누르고 말하기까지, 말하고 완료까지의 빈 시간을 **소리로 잡아 잘라낸다.** 엔진이 녹음을 풀 때 첫 소리와 마지막 소리의 위치를 재고,
재생은 첫 소리 0.15초 앞에서 시작해 마지막 소리 0.3초 뒤에서 끝난다. 두드림 같은 표시가 없으니 소리가 유일한 단서다.

**이름**

- 완료하면 무대 자리에 `녹음 2.3초`와 `듣기` `다시 녹음` `취소`, 그 아래 **이름 입력창**이 열리고 포커스를 받는다.
- **이름은 필수다.** 녹음은 열어 보기 전엔 뭐가 들었는지 모른다 — 카드에 뭐라도 써 있어야 목록에서 고른다.
  비운 채 저장을 누르면 이유를 말한다(원칙 2).
- 같은 이름을 막지 않는다. 다른 녹음이면 다른 콤보다.
- `듣기`는 저장 전에 훈련에서 들릴 그대로 — 앞뒤를 자르고, 지금 템포로.
- `다시 녹음`은 이름을 남기고 녹음만 새로 한다.
- 새 콤보는 목록 **맨 위**로. 오늘 담은 것이 제일 중요하다.
- 삭제는 한 번에. 대신 3초 되돌리기 토스트. (원칙 4)

**콤보 카드**

카드 왼쪽 전체가 훈련 포함 토글. 이름과 녹음 길이. `⋯`를 누르면 듣기·이름 고치기·다시 녹음·삭제가 펼쳐진다.
켜진 카드는 테두리가 액센트, 꺼진 카드는 회색에 글자도 죽는다.

- **이름 고치기**는 무대의 이름 상태로 올라간다 — 이름이 채워진 채, 녹음은 그대로. 저장하면 이름만 바뀐다.
  카드 안에서 편집하지 않는다 — 편집칸이 카드마다 있으면 v1 호출어 탭이 겪은 키보드·스크롤 문제가 그대로 온다.
- **다시 녹음**은 무대의 녹음 중 상태로 올라간다 — 이름은 그대로, 녹음만 새로. 취소하면 원래 녹음이 남는다.

**빈 목록**
첫 실행은 콤보가 없다. 목록 자리에 `눌러서 첫 콤보를 녹음해` 한 줄. 훈련의 `시작`은 지금처럼 이유를 말한다(8장).

## 5. 도메인 모델

```js
Combo  { id, name, on, ms, head, tail }   // ms: 녹음 길이, head/tail: 첫 소리·마지막 소리 위치(초)
Clip   { [comboId]: dataURL }             // 녹음 본체. 콤보와 따로 산다
```

**저장소 키**

| 키              | 내용             |
| --------------- | ---------------- |
| `sbc:combos`    | 콤보 목록        |
| `sbc:settings`  | 훈련 설정        |
| `sbc:clip:<id>` | 콤보 하나의 녹음 |

**녹음은 콤보와 따로 저장한다.** 초당 25KB(AAC, base64)라 콤보 목록 한 키에 같이 넣으면 콤보 하나를 켜고 끌 때마다
전부를 다시 쓴다. 본체를 못 읽으면(저장소 실패) 그 콤보는 훈련에서 건너뛴다.

**v1의 자료는 버린다.** `sbc:labels` `sbc:moves` `sbc:beats`는 읽지 않고 처음 읽을 때 지운다.
녹음이 없는 콤보(v1에서 만든 것)는 읽을 때 버린다 — 이제 부를 방법이 없다. 초기 콤보도 없다. 첫 실행은 빈 목록이다.

**저장소 용량은 문서에 없다.** 8초 × 25KB = 200KB, 콤보 30개면 6MB. 기기에서 20개쯤 넣어 재본다(9장).

## 6. 재생

콤보 하나를 트는 규칙. 훈련 중 호출과 카드의 듣기, 저장 전 듣기가 **같은 규칙**을 본다.

- 녹음의 `head − 0.15초`에서 시작해 `tail + 0.3초`에서 끝난다. 말은 손보다 조금 먼저 나오고, 끝은 여운을 남긴다.
- `head`·`tail`은 녹음을 풀 때 잰다 — 10ms 창의 RMS가 **최대치의 5%**를 처음·마지막으로 넘는 자리. 숨소리·손 소리보다 크고 말보다 작은 문턱이다.
  기기에서 첫 마디가 잘리면 문턱을 내리고, 앞이 길게 남으면 올린다.
- **템포는 재생 속도다.** 1.2면 1.2배 빨리, 음정도 그만큼 올라간다.
- 콤보가 끝나면 `콤보 간격`(+불규칙 폭 0~1.2초) 후 다음 콤보.
- 재생은 WebAudio가 샘플 단위로 예약한다. 녹음 본체는 앱이 켜질 때 전부 풀어 둔다 — 부를 때 풀면 첫 콤보가 늦는다.
- 일시정지·정지·건너뛰기는 재생을 **즉시 끊는다.** 나오던 말이 마저 나오지 않는다.

## 8. 공통 정책

### 죽은 버튼 금지

버튼은 항상 눌린다. 조건이 안 맞으면 **왜 안 되는지 말한다.**

| 버튼      | 조건 미충족 시                                  |
| --------- | ----------------------------------------------- |
| 시작      | 콤보가 없음 / 체크 안 됨 — 각각 다른 안내       |
| 콤보 저장 | 이름 없음 / 녹음 없음 — 각각 다른 안내          |
| 무대      | 마이크를 못 씀 — 무대 자체가 이유를 말한다      |

색은 상태를 알린다(액센트=가능, 회색=불가). 색만으로 막지는 않는다.

### 삭제와 되돌리기

확인 단계 없이 즉시 삭제하고 3초 토스트를 띄운다. **모든 토스트가 3초다** —
새 토스트를 만들 때 이 시계를 따로 정하지 마라.
되돌리기는 **원래 인덱스에** 복원한다. 맨 위나 맨 아래로 가지 않는다. 녹음 본체도 같이 돌아온다.
탭을 옮기면 토스트를 정리한다. 엉뚱한 것을 되돌리는 사고를 막는다.

### 플로팅 레이어

아래에서부터 쌓는다.

| 층              | z   | 하단 여백                |
| --------------- | --- | ------------------------ |
| 탭바            | 40  | 16px                     |
| 저장            | 30  | 96px                     |
| 되돌리기 토스트 | 40  | 96 또는 160px (FAB 유무) |
| 전체 화면       | 50  | —                        |

목록 하단 여백은 **위에 뜬 것의 유무에 따라 바뀐다.** 저장 버튼이 숨으면 콤보 목록 여백도 192 → 128px로 줄어 빈 공간이 남지 않는다.

여기에 **키보드 높이를 더한다.** 키보드는 스크롤 뷰를 줄이지 않고 그 위에 겹치므로, 안 더하면 마지막 줄에서 스크롤이 끝나고 편집칸이 키보드 밑에 갇힌다.
**콤보 저장은 키보드를 따라 올라간다** — 이름을 치는 중에 눌러야 한다.

**시트가 열리면 떠 있는 층을 걷어낸다.** TDS 바텀시트는 z를 걸지 않아서 위 표의 것들이 전부 시트 위로 올라온다.
탭바(z 40)는 아래로 밀어내고(220ms), FAB(z 30)는 아예 지운다.

### 앱을 나갔을 때

**백그라운드에서는 훈련을 이어갈 수 없다.** iOS가 백그라운드로 간 앱의 JS를 세운다.
토스 안의 미니앱이라 `UIBackgroundModes: audio`를 우리가 선언할 수 없고,
소리는 숨은 WebView에서 도는데 백그라운드 WKWebView는 더 확실히 멈춘다. **이건 우리가 못 넘는다.**

그래서 **나가는 순간 일시정지한다.**

- `background`에서만 멈춘다. `inactive`는 알림 배너·제어 센터처럼 스쳐 가는 것을 포함한다.
- **돌아와도 저절로 안 이어진다.** 재개는 사람이 누른다 — 주머니 속에서 훈련이 재개되면 안 된다.
- 나가는 순간 예약된 호출을 걷고 재생을 끊는다. 안 걷으면 돌아왔을 때 밀린 것이 한꺼번에 터진다.
- 재개하면 콤보를 처음부터 다시 튼다. 일시정지와 같은 경로다(4.1).
- 안드로이드도 같이 멈춘다. 한쪽만 다르게 굴면 무엇이 정상인지 알 수 없다.

**미뤄 둔 저장은 이때 밀어낸다.** 저장은 300ms 미루므로 그 창이 닫히기 전에 나가면 날아간다.
슬라이더는 앞에 110ms가 더 붙는다(4.2). 나가는 순간 미뤄 둔 것을 전부 쓴다.

**저장은 토스가 주는 저장소를 쓴다.** 미니앱을 완전히 종료했다 다시 열어도 남아야 하는 자료다 —
콤보·설정, 그리고 콤보별 녹음. `AsyncStorage`로는 안 남는다.

### 실패 처리

소리·화면잠금·저장소 접근은 전부 try/catch로 감싼다.
저장소는 동기 예외와 Promise 거부를 **둘 다** 처리한다. `.catch()`만으로는 모듈 부재를 못 잡는다.

**다만 이 침묵은 우리 눈도 가린다.** 쓰기가 통째로 실패해도 화면은 멀쩡하다.
저장이 실제로 되는지는 **기기에서 껐다 켜는 것으로만** 알 수 있다.

**마이크는 침묵하지 않는다.** 본 기능이라 못 쓰면 말한다(4.4).

### 접근성

아이콘 전용 버튼에는 `aria-label`. 터치 영역 최소 44px.
색 대비: `#006064` 위 흰 글자는 약 7:1.

## 11. 판단 근거 기록

나중에 뒤집고 싶어질 결정들과 그 이유.

**TTS를 버린 이유 (v2)**
v1은 동작마다 길이를 정하고 TTS가 이름을 읽었다. 실기기에서 두드린 리듬을 TTS에 태워 보니 말 하나를 읽는 시간이 하한이라
잽잽 더블(0.2초)이 뭉개졌다. 말 속도를 2.0으로 올리면 갈리지만 그건 목소리를 망가뜨린 대가다.
클릭음을 겹치는 안(박자는 클릭, 이름은 말)은 3분에 100번 울린다. 녹음은 "무엇"과 "언제"를 한 번에 담고 하한이 없다.
그리고 동작·호출어·파서·리듬 모델 전부가 TTS를 위해 있었다 — TTS가 나가면 같이 나가는 게 맞다.
토스 모듈엔 마이크가 없어 숨은 WebView의 `getUserMedia`로 하는데, 2026-09-13 iOS에서 권한·녹음·재생이 됐다.

**두드리기를 버린 이유 (v2)**
녹음 전에 "두드리면서 말하기"를 만들었다 — 두드린 시각으로 동작별 칩과 비트 트랙을 살리려고.
사용자가 써 보니 두드릴 이유가 없었다. 녹음이 리듬을 다 갖고 있고, 동작별 칩은 원칙 1에서 보면 없어도 되는 것이었다.
앞뒤 침묵은 두드림 대신 소리로 잡는다.

**이름을 필수로 한 이유**
녹음은 열어 보기 전엔 뭐가 들었는지 모른다. 카드에 뭐라도 써 있어야 목록에서 고른다.
원칙 3과 부딪히지만, 말한 걸 한 단어로 적는 것과 동작을 형식에 맞춰 적는 것은 다른 마찰이다.

**애니메이션으로 콤보를 보여주는 안을 버린 이유**
벡터 골격 애니메이션은 실사 수준이 안 나온다. 더 중요하게는, 화면을 응시하게 만들어 자세가 무너진다.

**리듬게임 UI를 안 넣은 이유**
어긋난 리듬을 눈으로 따라가면 잘못된 타이밍을 배운다. 판정·점수도 같은 이유로 없다. 녹음이 들어온 뒤에도 같다 — 화면은 보조다.

**백그라운드에서 시간을 맞추지 않고 멈추는 이유**
돌아왔을 때 나가 있던 만큼 시계를 당기면 시간은 맞는다. 그런데 그동안의 호출은 못 들은 것이고,
오래 나갔다 오면 라운드가 이미 끝나 있다. **안 들리는 동안 흘러간 것은 훈련이 아니다.**
그대로 두는 안은 더 나쁘다 — 조용히 밀리고, 밀린 예약이 돌아올 때 터져서 고장인지도 모른다.
멈추면 잃는 것이 분명해지고, 되살리는 시점을 사람이 정한다.

**제품화하지 않는 이유**
동일 기능 앱이 10개 이상 있고 대부분 무료거나 $3 수준이다. 유일하게 비어 있는 자리는 "콤보를 집어넣는 마찰"인데,
그것만으로는 방어 가능한 해자가 못 된다. 개인 도구로서의 가치는 충분하다.
