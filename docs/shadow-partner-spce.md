# 쉐도우 코치 — 기획 및 정책 v1.0

킥복싱 쉐도우 트레이닝용 개인 도구. 체육관에서 배운 콤보를 저장하고, 라운드 중에 음성으로 불러준다.

---

## 1. 제품 정의

**해결하는 문제**
체육관에서 배운 콤보를 집에 오면 까먹는다. 기존 앱들은 *앱이 생성한 콤보*를 불러주는 생성기 중심이라, *내가 배운 콤보*를 드릴하는 용도로는 어긋난다.

**사용자**
본인. 배포·수익화 계획 없음.

**범위 밖**
계정, 동기화, 통계 누적, 소셜, 튜토리얼 영상, 자세 인식.

---

## 2. 설계 원칙

원칙은 취향이 아니라 이 앱의 사용 맥락에서 나온다. 충돌하면 위쪽이 이긴다.

| #   | 원칙                                       | 근거                                                                                                                  |
| --- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| 1   | **화면을 안 봐도 훈련이 된다**             | 쉐도우복싱은 거울이나 허공을 봐야 한다. 화면은 보조이지 주인공이 아니다.                                              |
| 2   | **죽은 버튼을 두지 않는다**                | 비활성 버튼은 클릭 이벤트조차 발생하지 않아 "고장"으로 읽힌다. 실제로 이 앱에서 시작 버튼이 이 문제로 두 차례 막혔다. |
| 3   | **적는 마찰이 없다**                       | 이 앱의 유일한 차별점. 형식을 강제하는 순간 존재 이유가 사라진다.                                                     |
| 4   | **되돌릴 수 있으면 확인하지 않는다**       | 확인 단계와 되돌리기를 둘 다 두면 마찰만 늘고 안전은 그대로다.                                                        |
| 5   | **떠 있는 것은 최소한으로**                | 하단 플로팅 요소가 겹치면 콘텐츠가 밀린다. 층마다 존재 이유가 있어야 한다.                                            |
| 6   | **부가 기능 실패가 본 기능을 막지 않는다** | 오디오·음성·저장소가 없는 환경에서도 타이머는 돌아야 한다.                                                            |

원칙 3은 **동작을 적는** 마찰이다. 리듬은 글로 못 적는다 — 체육관에서 배운 콤보는 동작의 나열이 아니라
어디서 몰아치고 어디서 쉬는지까지다. 그래서 리듬은 **두드려서** 담는다(4.4). 동작을 적는 길은 그대로 한 줄이다.

### 색상

블랙, 화이트, `#006064` 세 가지. 상수 `ACCENT` 하나로 관리한다.
회색 계열은 블랙-화이트 사이 톤이므로 팔레트 위반이 아니다.
`#006064`는 검정 위에서 어두워 **본문 텍스트에는 쓰지 않는다.** 배경·테두리·강조 링에만 쓴다.

## 3. 정보 구조

```
쉐도우 코치
├─ 훈련 (탭)
│   ├─ 훈련 설정 ......... 바텀시트
│   └─ 훈련 완료 ......... 전체 화면
├─ 콤보 (탭) ............. 두드리는 무대 + 슬롯 + 목록
│   └─ 동작 고르기 ....... 바텀시트 (슬롯 하나를 채운다)
└─ 호출어 (탭)
    └─ 동작 추가 ......... 바텀시트
```

탭 3개는 하단 플로팅 바. 아이콘 위, 한글 아래.

**갔다가 돌아오는 화면은 전부 바텀시트다.** 전체 화면은 훈련 완료 하나만 남는다 —
나가는 길을 우리가 정하는 화면이라 뒤로가기가 있으면 안 된다.

이 결론은 두 번 뒤집혔다. 원래 전부 겹침(RN `Modal`)이었는데, 겹침은 별도 네이티브 층이라
**토스 상태바까지 덮어버리고** 토스는 그 헤더를 숨기는 길을 주지 않는다. 그래서 라우트로 내보냈다
(`/add-move`). 라우트는 그 문제를 풀었지만 값을 물었다 — 돌아올 때 결과를 못 들고 오고,
화면이 갈라져 자료를 트리 밖으로 빼야 했고, 전환 중 흰 번쩍임·키보드·자동 포커스를 각각 손봐야 했다.

TDS 바텀시트는 `Modal`이 아니라 **앱 트리 안의 `position:absolute` 뷰**다
(`BottomSheetRoot`). 그래서 토스 헤더를 덮지 않으면서도 라우트가 물던 값을 전부 안 문다.
겹침을 피하려던 이유가 겹침의 한 종류로 풀린 셈이다 — 문제는 "겹침"이 아니라 "네이티브 층"이었다.

덤으로 얻은 것: 동작 고르기는 뒤의 슬롯 줄이 보여서 어느 자리를 채우고 있는지 보며 고를 수 있다.
시트는 아래에서 올라온다(TDS `spring.quick`, stiffness 800 / damping 55 고정).

**동작 고르기·동작 추가 시트는 화면의 2/3로 키를 고정한다**(`SHEET_RATIO`). TDS 기본은 내용에 맞춰 늘어나고 최대 0.7까지만 막는데, 분류를 옮기거나 오류 한 줄이 붙을 때마다 CTA와 목록이 다른 자리로 옮겨 다닌다. 내용이 짧으면 아래를 비워 두고, 넘치면 본문이 스크롤된다.

**키보드가 오르면 그 위에 남는 자리로 줄인다**(`useSheetHeight`). TDS는 키보드 높이만큼 시트를 위로 밀기 때문에 키를 고정한 채로 두면 핸들과 헤더가 화면 밖으로 나간다. 키보드가 내려가면 다시 2/3다. 구아키텍처 안드로이드는 TDS가 시트를 밀지 않아서 줄이지도 않는다.

이때 위쪽으로 비켜 두는 120은 **안전영역이 아니라 상수다.** 토스 헤더가 앱 위에 그려지는데 `insets.top`이 그 높이를 알려주지 않아서, 안전영역으로 계산한 첫 판이 실기기에서 그대로 잘렸다.

## 4. 화면 명세

### 4.1 훈련

**목적** 라운드를 돌리고 콤보를 듣는다. 앱의 기본 화면.

**구성**

| 요소          | 설명                                                                                          |
| ------------- | --------------------------------------------------------------------------------------------- |
| 원형 스톱워치 | 320px. 남은 시간이 링으로 줄어든다. 중앙에 시간, 그 위에 상태(`라운드 2 / 3`, `휴식`, `준비`) |
| 콤보 칩       | 3단계 — 지난 동작(거의 안 보임) / 현재(액센트 배경, 1.1배) / 다음(회색, 읽힘)                 |
| 비트 트랙     | 동작마다 다음까지 기다리는 시간에 **비례한 폭**(7장). 두드린 리듬이 있으면 그 모양이 그대로 보인다 |
| 유지 구간     | 콤보 사이 빈 시간. 점선 칩에 안내(`스텝`, `가드 올리고` 등), 회색 게이지로 다음 콤보까지 표시 |
| 컨트롤        | 대기 시 `시작` / 진행 중 `일시정지`·`건너뛰기`·`정지`                                         |
| 요약 알약     | `랜덤 · 3라운드 · 3:00 / 1:00`. 현재 설정 표시 겸 설정 시트 입구                              |

**정책**

- 상태 표시는 절대 배치라 비어 있어도 시간의 중앙 정렬에 영향을 주지 않는다.
- 유지 구간 안내는 **소리를 내지 않는다.** 3분에 30회 가까이 되어 시끄럽고, 진짜 호출과 헷갈린다.
- 진행 중 스킵은 `없음` 모드에서 숨긴다. 부를 콤보가 없다.
- 일시정지 후 재개하면 콤보를 **처음부터** 다시 부른다. 중간 복구는 복잡도 대비 실익이 없다.
- **앱을 나가면 일시정지한다.** 돌아와도 저절로 안 이어진다 — 9장 "앱을 나갔을 때".
- `횟수` 모드에서 일시정지 후 재개하면 남은 횟수를 남은 시간에 재배분한다. 총 횟수가 보장된다.

**흐름**

```
대기 ──시작──▶ 준비(5초, 비프)
                  │ 벨 3회
                  ▼
              라운드 ◀──────┐
                  │          │ 벨 3회
     10초 전 클래퍼          │
                  │ 벨 1회   │
                  ▼          │
          마지막 라운드? ─N─▶ 휴식
                  │Y
                  ▼
              훈련 완료
```

**실패 처리**
`시작`은 상태 전환을 먼저 수행하고 소리·음성·화면잠금은 그 뒤에 시도한다.
부가 기능이 실패해도 타이머는 반드시 돈다. (원칙 6)

### 4.2 훈련 설정 — 바텀시트

**목적** 훈련 관련 설정 전부. 입구는 요약 알약과 톱니 두 곳이지만 **화면은 하나다.**

> 모드 버튼을 눌러 시트를 여는 안은 폐기했다. 선택과 열기를 한 버튼이 겸하면 예측이 안 되고, `없음` 모드는 설정할 것이 없어 예외가 생기며, 설정 입구가 둘로 갈린다.

**구성** 모드 → 라운드 → 라운드당 호출 → 라운드 시간 → 휴식 / 템포 → 콤보 간격 → 간격 불규칙 / 목소리 → 말 속도 → 소리 테스트

**정책**

- 훈련 중에는 **모드·라운드·시간·휴식이 잠긴다**(투명도 40%). 진행 중인 타이머와 스케줄을 깨뜨린다.
- 반대로 **템포·간격·목소리·말 속도는 살아 있다.** 라운드 중에 "너무 빠르다" 싶으면 즉시 늦출 수 있다.
- 잠긴 이유를 시트 상단에 한 줄로 알린다.
- 시간 설정은 스테퍼(`3:00` 표기). 숫자 입력창은 키보드를 부르고 초 단위 환산을 요구한다.

### 4.3 훈련 완료 — 전체 화면

**목적** 마친 직후는 앱을 다시 열게 만드는 유일한 순간. 여기서 뭘 했는지 보여준다.

**구성** `STAGE CLEAR` → `수고했어` → 통계 4행 → `TO BE CONTINUED...` → `한 번 더` / `그만하기`

**정책**

- 절제된 다른 화면과 달리 **여기에만 성격을 몰아준다.** 숫자 카운트업(900ms, 감속), 모노스페이스 자간, `step-end` 깜빡임.
- `TO BE CONTINUED...`는 흰색. 액센트는 검정 위에서 어둡고, 오락실 화면도 흰색·노란색이 깜빡인다.
- 통계는 세션 시작 시 초기화되고 콤보가 호출될 때마다 누적된다. **저장하지 않는다** — 기록 누적은 v1 범위 밖.
- 탭바까지 덮는다. 나가는 길은 두 버튼뿐.

### 4.4 콤보

**목적** 콤보를 **두드려서** 리듬을 담고, 그 자리에 동작을 매기고, 훈련에 넣을 것을 고른다.

**구성** 무대(샌드백) → 슬롯 줄 + 한 줄 입력 → 중복 안내 → 콤보 카드 목록 / 하단 저장 버튼

**흐름**

```
쉬는 무대 ──첫 터치──▶ 두드리는 중 ──완료──▶ 슬롯 채우기 ──저장──▶ 목록 맨 위
                          │ 취소                 │ 다시 두드리기
                          ▼                      ▼
                        쉬는 무대              두드리는 중 (동작은 남긴다)
```

**무대**

- 콤보 탭 **상단, 고정 높이.** 반투명 샌드백 하나. 시트가 아니다 — TDS 시트의 끌어서 닫기가 길게 누르는 손과 싸운다.
  전체 화면도 아니다 — 3장의 이유로 겹침은 훈련 완료 하나만 남긴다.
- **첫 터치가 시작이다.** 시작 버튼을 따로 두지 않는다. 쉬는 무대에는 `두드려서 시작` 한 줄만.
- 탭마다 시각을 기록한다. **`nativeEvent.timestamp`로 잰다** — JS가 바쁘면 `Date.now()`는 밀린다.
- 탭마다 햅틱. 손이 닿았다는 걸 손으로 안다. 소리는 내지 않는다 — 두드리는 소리와 말이 섞이면 안 된다.
- 두드리는 동안 **목록을 죽인다**(흐리게, 터치·스크롤 없음). 무대가 스크롤 안에 있으면 세로로 끌리는 손이 탭을 먹는다.
- 끝은 **명시적 완료 버튼.** "n초 손을 떼면 자동 완료"는 마지막 동작 뒤의 쉼을 두드림으로 착각한다.
- 취소는 언제든. 두드린 것을 버리고 쉬는 무대로.
- 두드린 간격은 **양자화하지도, 하한을 걸지도 않는다.** 두드린 그대로다. 들리는 하한은 말 속도가 정한다(7장).
- 탭 수의 상한은 콤보 길이 상한과 같다. 탭 하나짜리도 콤보다 — 간격이 없을 뿐이다.

**슬롯**

- 완료하면 탭 수만큼 빈 슬롯이 줄로 선다. 첫 슬롯이 열려 있다.
- 슬롯을 누르면 동작 고르기 시트(4.5). 고르면 채워지고 **다음 빈 슬롯이 열린다.** 마지막을 채우면 시트가 닫힌다.
- **한 줄로도 적는다.** 슬롯 줄 아래 입력창에 `잽잽투로우킥`을 치면 파서(6장)가 푼 동작이 슬롯에 **순서대로** 들어간다.
  - 적은 동작이 슬롯보다 적으면 앞에서부터 채우고 나머지는 비어 있다.
  - 적은 동작이 슬롯보다 많으면 넘치는 건 안 들어간다. 안내한다 — `두드린 건 4개, 적은 건 5개`.
  - 못 알아들은 말은 그대로 보존되고 안내된다. 사용자가 친 말이 사라지면 안 된다.
- 슬롯과 입력창은 **항상 같은 것을 가리킨다.** 시트로 채우면 입력창이 다시 써지고, 입력창을 고치면 슬롯이 따라온다.
- 채워진 슬롯을 누르면 **비운다.** 자리는 남는다 — 칩처럼 사라지지 않는다. 자리가 곧 두드린 박이다.
- **다시 두드리기**는 리듬만 바꾼다. 동작은 앞에서부터 남기고, 탭이 줄면 뒤가 잘리고 늘면 뒤가 빈다.
- **듣기**는 저장 전에 있다. 채워진 슬롯은 그 동작을 **지금 말 속도의 실제 목소리로** 부르고, 빈 슬롯은 클릭음이다.
  두드린 모양과 실제로 들릴 것을 한 단추로 확인한다 — 말 속도에서 뭉개지면 여기서 안다.
- 저장 버튼은 **슬롯 단계에 들어가면** 뜬다. 빈 슬롯이 있어도 뜬다 — 눌러야 이유를 물을 수 있다(원칙 2).
- 새 콤보는 목록 **맨 위**로. 오늘 적은 것이 제일 중요하다.
- 삭제는 한 번에. 대신 3초 되돌리기 토스트. (원칙 4)
- 중복은 **동작 순서가 완전히 같을 때만.** 리듬은 보지 않는다 — 같은 순서 다른 리듬은 새 콤보가 아니라 수정이다.

**중복 처리**

| 상황                           | 처리                                             |
| ------------------------------ | ------------------------------------------------ |
| 같은 콤보가 훈련에 들어가 있음 | 저장 차단 + `목록에서 보기`                      |
| 같은 콤보가 훈련에서 빠져 있음 | 저장 차단 + `목록에서 보기` + `훈련에 다시 넣기` |
| 수정 중 자기 자신              | 중복에서 제외                                    |

`목록에서 보기`는 해당 카드로 스크롤하고 `#006064` 링을 2.4초 두른다.

**콤보 카드**

카드 왼쪽 전체가 훈련 포함 토글. `⋯`를 누르면 듣기·수정·삭제가 펼쳐진다.
켜진 카드는 테두리가 액센트, 꺼진 카드는 회색에 글자도 죽는다.

- **수정**은 슬롯 단계로 들어간다 — 동작이 채워진 채, 리듬이 있으면 그대로. 리듬을 바꾸려면 거기서 다시 두드린다.
- 리듬이 없는 콤보(예전에 저장한 것)는 동작 길이로 재생된다(7장). **카드에 리듬 유무를 표시하지 않는다** —
  화면은 보조다(원칙 1). 듣기와 비트 트랙이 이미 보여준다.

---

### 4.5 동작 고르기 — 바텀시트

**목적** 슬롯 하나를 타이핑 없이 탭만으로 채운다.

**정책**

- 분류 탭(펀치/킥/방어/풋워크)으로 한 번에 5~7개만 노출. 20개 이상을 세로로 펼치면 스크롤 지옥이 된다.
- 분류는 **탭을 눌러서도, 목록을 쓸어서도** 넘어간다. 스와이프는 탭을 대신하지 않고 얹기만 한다 —
  제스처만 아는 사람이 없어야 한다. 끝에서는 감기지 않는다. 감기면 어디까지 왔는지 감이 사라진다.
- 슬롯 줄은 **분류 탭 바로 아래.** 어느 자리를 채우고 있는지 보여야 한다.
  시트에서는 바닥이 CTA 자리라 거기 두면 목록이 밀린다(키는 3장이 고정했다).
- 동작을 고르면 열린 슬롯이 채워지고 **다음 빈 슬롯이 열린다.** 마지막을 채우면 시트가 닫힌다.
- 슬롯을 눌러 채울 자리를 옮길 수 있다. 비우는 건 시트 밖에서 한다(4.4).
- 슬롯 줄에만 배경을 둔다. 스크롤되는 버튼 위에 겹치면 글자가 안 읽힌다.

---

### 4.6 호출어

**목적** 코치가 뭐라고 부를지 정한다. 여기서 정한 말은 **파서에도 자동 등록된다.**

**정책**

- 평소엔 **글자만.** 누르면 그 줄만 편집으로 바뀐다. 20개 넘는 입력 상자를 한 화면에 깔지 않는다.
- 기본 동작과 직접 추가한 동작을 **한 목록**으로. 같은 성격을 두 섹션으로 나누지 않는다.
- 분류는 탭을 눌러서도, 목록을 쓸어서도 넘어간다(4.5와 같은 규칙). 넘어가면 열려 있던 편집 줄은 닫는다 —
  그 줄은 화면에서 사라지므로 열린 채 두면 어디를 고치고 있었는지 알 수 없다.
- 접힌 줄에도 현재 길이를 표시한다. 열지 않고 훑을 수 있다.
- 줄을 펼치면 **입력칸으로 굴려 간다.** 편집칸은 자동으로 포커스를 받으므로 스크롤이 따라가지 않으면
  포커스가 키보드 아래에 있게 된다. 목록 아래쪽 줄은 동작 길이와 삭제에도 손이 닿지 않는다.
- 겨누는 것은 **두 번**이다. 펼치는 순간에는 아래 여백에 키보드가 아직 안 들어가 있어서 마지막 줄이
  굴릴 수 있는 끝에 걸린다. 여백이 늘어난 뒤 한 번 더 겨눈다. 줄어들 때는 겨누지 않는다 —
  키보드를 내린 사람을 다시 끌고 갈 이유가 없다.
- **타자 중에는 동작 추가 FAB을 걷어낸다.** 키보드 위 그 자리가 편집칸의 들어보기·확인 단추 자리다.
- 모든 동작이 길이를 바꿀 수 있다. 기본값은 추정치일 뿐이다.
- 되돌리기는 이름과 길이를 **함께** 되돌린다.
- 동작 삭제는 콤보 삭제보다 위험하다 — 그 동작을 쓰던 콤보에서도 빠지고, 비어버린 콤보는 사라진다. 따라서:
  - 토스트에 영향 범위를 표시한다(`콤보 2개에서 빠짐`)
  - 되돌리면 동작·콤보·이름·길이가 전부 복원된다

**동작 추가 진입**
56px 원형 버튼, 오른쪽 아래. 저장 버튼과 형태를 달리해 위계를 만든다.
콤보 저장은 결정적 동작이라 크고, 동작 추가는 시트를 여는 입구이므로 작다.

## 5. 도메인 모델

```js
Move   { id, name, kind, beat, num?, numCall?, aliases[] }
Combo  { id, moves: [moveId], on, rhythm?: [sec] }
Label  { [moveId]: string }   // 호출어 덮어쓰기
Beat   { [moveId]: number }   // 길이 덮어쓰기
```

**kind** `punch` | `kick` | `def` | `move`

**저장소 키**

| 키             | 내용             |
| -------------- | ---------------- |
| `sbc:combos`   | 콤보 목록        |
| `sbc:settings` | 훈련 설정        |
| `sbc:labels`   | 호출어 덮어쓰기  |
| `sbc:moves`    | 직접 추가한 동작 |
| `sbc:beats`    | 길이 덮어쓰기    |

덮어쓰기는 기본값을 **대체하지 않고 위에 얹는다.** 되돌리면 원래 값이 그대로 살아난다.

**`rhythm`은 두드린 간격(초)이다.** i번째 값은 i번째 동작에서 다음 동작까지 — 그래서 **동작 수보다 하나 적다.**
마지막 동작 뒤는 두드려서 얻을 수 없다. 없으면 동작마다 정해진 길이를 따른다(7장).
예전에 저장한 콤보에는 없고, 없는 채로 둔다 — 마이그레이션하지 않는다.

## 6. 콤보 파서

슬롯을 한 줄로 채울 때 쓴다(4.4). 입력 형식을 강제하지 않는다. 아래가 전부 같은 결과다.

```
원원투        원,원,투       원 원 투       1-2-2
잽잽스트레이트  잽 잽 스트레이트
```

**매칭 우선순위**

1. 반복 지시어 — `더블` `트리플` (뒤 동작에 적용)
2. 반복 수량 — `x2` `2번` `두번` (앞 동작에 적용)
3. **공백을 넘는 이름** — 토큰 최대 4개를 이어붙여 사전 조회, **긴 쪽이 이긴다**
4. 숫자 나열 — `123` → `1` `2` `3`
5. 토큰 단독 일치
6. 토큰 내부 탐욕 분해 — 띄어쓰기 없는 입력 처리

3번이 핵심이다. 이것이 없으면 `라이트훅`과 `라이트 훅`이 다르게 해석된다.

**전처리**
구분자(`- , / > · | + &`)를 공백으로, 붙은 반복 표현(`더블잽`, `훅x2`, `잽2번`)을 띄운다.

**예시**

| 입력                     | 결과                     |
| ------------------------ | ------------------------ |
| `라이트훅` / `라이트 훅` | 라이트훅                 |
| `라이트 오버훅`\*        | 라이트 오버훅 (한 동작)  |
| `더블잽 투`              | 잽 잽 스트레이트         |
| `훅x2 로우킥`            | 레프트훅 레프트훅 로우킥 |
| `1-2 로우킥`             | 잽 스트레이트 로우킥     |

\* 직접 추가한 동작인 경우

**알려진 한계**

- 등록한 이름의 일부만으로는 못 찾는다. `라이트 오버훅`을 등록하고 `오버훅`만 치면 실패. 짧게 부르려면 이름 자체를 짧게 하거나 별칭이 필요하다(자료구조엔 있으나 입력 UI 미구현).
- 이름 충돌 시 긴 쪽이 이긴다. `원투`라는 동작을 추가하면 `원 투`가 그 동작 하나로 해석된다. 파싱 칩이 즉시 보여주므로 눈으로 잡을 수 있다.

## 7. 리듬 모델

박자의 주인은 둘이다. **두드린 리듬이 있으면 콤보가, 없으면 동작이** 갖는다.
동작마다 소요 시간이 다르고, 그것이 리듬 없는 콤보의 박자를 만든다.

**5단계 척도**

| 단계      | 초   | 기본 배정                                          |
| --------- | ---- | -------------------------------------------------- |
| 아주 짧게 | 0.40 | 잽                                                 |
| 짧게      | 0.50 | 스트레이트, 슬립, 더킹, 블로킹, 스텝, 백스텝, 피벗 |
| 보통      | 0.65 | 훅, 어퍼, 바디, 니킥, 위빙, 스위치                 |
| 길게      | 0.85 | 로우킥, 미들킥, 푸시킥                             |
| 아주 길게 | 1.05 | 하이킥                                             |

정확도보다 **상대적 비율**이 중요하다. 전체 속도는 템포 배율로 맞춘다.
슬라이더 대신 5단계인 이유: 미세 조정에 시간을 쓰게 만들 만한 정보가 없다.

**타이밍**
`다음 동작까지 = (두드린 간격이 있으면 그것, 없으면 현재 동작 길이) ÷ 템포`
**마지막 동작은 언제나 동작 길이다** — 두드려서 얻을 수 없는 자리다.
콤보가 끝나면 `콤보 간격`(+불규칙 폭 0~1.2초) 후 다음 콤보.
호출·미리듣기·비트 트랙이 **같은 식 하나**(`comboSteps`)를 본다. 눈과 귀가 어긋나면 안 된다.

**들리는 하한은 말 속도가 정한다.** TTS는 앞 말을 끊지 않고 줄을 세우므로, 간격이 그 말을 읽는 시간보다
짧으면 읽는 시간만큼으로 늘어난다. 2026-09-13 기기에서 잽 4연타를 들었다 — 말 속도 1.15에서는
0.2·0.3·0.4가 같게 들리고 0.5부터 갈렸고, **2.0에서는 넷이 다 갈렸다.**
그래서 하한을 코드로 걸지 않는다. 걸면 말 속도를 올린 사람에게서 두드린 것을 빼앗는다.
대신 저장 전에 지금 말 속도의 실제 목소리로 들려준다(4.4). 뭉개지면 그 자리에서 안다.

## 9. 공통 정책

### 죽은 버튼 금지

버튼은 항상 눌린다. 조건이 안 맞으면 **왜 안 되는지 말한다.**

| 버튼      | 조건 미충족 시                              |
| --------- | ------------------------------------------- |
| 시작      | 콤보가 없음 / 체크 안 됨 — 각각 다른 안내   |
| 콤보 저장 | 빈 슬롯 / 인식 실패 / 넘친 동작 / 중복 — 각각 다른 안내 |
| 동작 추가 | 이름 없음 / 이미 등록된 말                  |

색은 상태를 알린다(액센트=가능, 회색=불가). 색만으로 막지는 않는다.

### 삭제와 되돌리기

확인 단계 없이 즉시 삭제하고 3초 토스트를 띄운다. **모든 토스트가 3초다** —
새 토스트를 만들 때 이 시계를 따로 정하지 마라.
되돌리기는 **원래 인덱스에** 복원한다. 맨 위나 맨 아래로 가지 않는다.
탭을 옮기면 토스트를 정리한다. 엉뚱한 것을 되돌리는 사고를 막는다.

### 플로팅 레이어

아래에서부터 쌓는다.

| 층               | z   | 하단 여백                |
| ---------------- | --- | ------------------------ |
| 탭바             | 40  | 16px                     |
| 저장 / 동작 추가 | 30  | 96px                     |
| 되돌리기 토스트  | 40  | 96 또는 160px (FAB 유무) |
| 전체 화면        | 50  | —                        |

목록 하단 여백은 **위에 뜬 것의 유무에 따라 바뀐다.** 저장 버튼이 숨으면 콤보 목록 여백도 192 → 128px로 줄어 빈 공간이 남지 않는다.

여기에 **키보드 높이를 더한다.** 키보드는 스크롤 뷰를 줄이지 않고 그 위에 겹치므로, 안 더하면 마지막 줄에서 스크롤이 끝나고 편집칸이 키보드 밑에 갇힌다.

키보드가 올라올 때 FAB의 방향은 둘로 갈린다 — **콤보 저장은 따라 올라가고**(타자 중에 눌러야 한다) **동작 추가는 사라진다**(그 자리는 편집칸 단추 자리다).

**시트가 열리면 떠 있는 층을 걷어낸다.** TDS 바텀시트는 z를 걸지 않아서 위 표의 것들이 전부 시트 위로 올라온다.
탭바(z 40)는 아래로 밀어내고(220ms), FAB(z 30)는 아예 지운다. 셋 중 하나라도 열려 있으면 적용된다 —
설정·동작 고르기·동작 추가.

### 앱을 나갔을 때

**백그라운드에서는 훈련을 이어갈 수 없다.** iOS가 백그라운드로 간 앱의 JS를 세운다.
나오던 말 한 마디는 네이티브 TTS가 마저 읽고, 다음을 예약할 JS가 없어 거기서 끊긴다.
토스 안의 미니앱이라 `UIBackgroundModes: audio`를 우리가 선언할 수 없고,
TTS는 숨은 WebView에서 도는데 백그라운드 WKWebView는 더 확실히 멈춘다. **이건 우리가 못 넘는다.**

그래서 **나가는 순간 일시정지한다.**

- `background`에서만 멈춘다. `inactive`는 알림 배너·제어 센터처럼 스쳐 가는 것을 포함한다.
- **돌아와도 저절로 안 이어진다.** 재개는 사람이 누른다 — 주머니 속에서 훈련이 재개되면 안 된다.
- 나가는 순간 예약된 호출을 걷는다. 안 걷으면 돌아왔을 때 밀린 것이 한꺼번에 터진다.
- 재개하면 콤보를 처음부터 다시 부른다. 일시정지와 같은 경로다(4.1).
- 안드로이드도 같이 멈춘다. 거기서는 계속 돌 수도 있으나, 한쪽만 다르게 굴면
  무엇이 정상인지 알 수 없다.

**미뤄 둔 저장은 이때 밀어낸다.** 저장은 300ms 미루므로 그 창이 닫히기 전에 나가면 날아간다.
슬라이더는 앞에 110ms가 더 붙는다(4.2). 나가는 순간 미뤄 둔 것을 전부 쓴다.

**저장은 토스가 주는 저장소를 쓴다.** 미니앱을 완전히 종료했다 다시 열어도 남아야 하는 자료다 —
콤보·설정·호출어·직접 추가한 동작·동작 길이 다섯 조각. `AsyncStorage`로는 안 남는다.

### 실패 처리

소리·음성·화면잠금·저장소 접근은 전부 try/catch로 감싼다.
저장소는 동기 예외와 Promise 거부를 **둘 다** 처리한다. `.catch()`만으로는 모듈 부재를 못 잡는다.

**다만 이 침묵은 우리 눈도 가린다.** 쓰기가 통째로 실패해도 화면은 멀쩡하다.
저장이 실제로 되는지는 **기기에서 껐다 켜는 것으로만** 알 수 있다.

### 접근성

아이콘 전용 버튼에는 `aria-label`. 터치 영역 최소 44px.
색 대비: `#006064` 위 흰 글자는 약 7:1.

## 12. 판단 근거 기록

나중에 뒤집고 싶어질 결정들과 그 이유.

**애니메이션으로 콤보를 보여주는 안을 버린 이유**
벡터 골격 애니메이션은 실사 수준이 안 나온다. 더 중요하게는, 화면을 응시하게 만들어 자세가 무너진다. 대신 비트 트랙으로 박자만 시각화했다.

**리듬게임 UI를 안 넣은 이유**
`speechSynthesis`는 첫 호출 지연이 100~400ms 튄다. 노트를 예약 시각에 떨어뜨려도 실제 목소리는 늦게 나온다. 어긋난 리듬을 눈으로 따라가면 잘못된 타이밍을 배운다. 판정·점수도 같은 이유로 없다.

**콤보의 리듬을 두드려서 담는 이유**
콤보는 동작의 나열이 아니다. 체육관에서 배운 건 `잽 잽 스트레이트`가 아니라 "잽잽" 하고 붙여 치고 한 박 쉬고 스트레이트다.
글로는 그 쉼을 못 적는다. 동작마다 길이를 정해 두는 지금 모델(7장)은 모든 콤보를 같은 박자로 만든다.
두드리는 건 마찰이 아니라 **적을 수 없던 것을 적는 길**이다 — 원칙 3은 동작을 적는 마찰이고, 그 길은 한 줄 그대로 남긴다.

**두드린 간격을 보정하지 않는 이유**
처음엔 하한을 걸거나 가장 짧은 간격이 하한에 닿게 전체를 늘리려 했다. 스파이크에서 하한이 코드의 것이 아니라
**말 속도의 것**으로 드러났다 — 2.0에서는 0.2초도 갈린다. 코드가 보정하면 말 속도를 올린 사람에게서 두드린 것을 빼앗는다.
대신 저장 전에 실제 목소리로 들려줘서, 뭉개지는지를 사람이 듣고 정하게 한다.

**백그라운드에서 시간을 맞추지 않고 멈추는 이유**
돌아왔을 때 나가 있던 만큼 시계를 당기면 시간은 맞는다. 그런데 그동안의 호출어는 못 들은 것이고,
오래 나갔다 오면 라운드가 이미 끝나 있다. **안 들리는 동안 흘러간 것은 훈련이 아니다.**
그대로 두는 안은 더 나쁘다 — 조용히 밀리고, 밀린 예약이 돌아올 때 터져서 고장인지도 모른다.
멈추면 잃는 것이 분명해지고, 되살리는 시점을 사람이 정한다.

**제품화하지 않는 이유**
동일 기능 앱이 10개 이상 있고 대부분 무료거나 $3 수준이다. 유일하게 비어 있는 자리는 "콤보를 집어넣는 마찰"인데, 그것만으로는 방어 가능한 해자가 못 된다. 개인 도구로서의 가치는 충분하다.
